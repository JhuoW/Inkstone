# 发行与版本策略

项目使用 `主版本.次版本.补丁版本` 格式，并按当前产品约定递增：

- 小更新、问题修复和小范围操作优化：递增补丁版本，例如 `0.6.0 → 0.6.1`。
- 主要功能更新：递增次版本，补丁版本归零，例如 `0.5.2 → 0.6.0`。
- 上一轮 Windows 稳定化与修复基线为 `0.5.0`；当前行内公式与分层右键菜单更新为 `0.6.0`。

`package.json` 的版本、`package-lock.json` 的根版本及 `packages[""].version` 必须一致。安装程序、便携包、PE 资源和包内 `package.json` 均由这一版本重新构建；修改文件名不构成版本升级。

每个版本保留自己的源码/构建快照、校验和与验收记录。0.6.0–0.6.4 的详细验收文件已从仓库移除，归档在提交 [`f821158`](https://github.com/JhuoW/Inkstone/tree/f8211586bca40d549c63442c0aa59b19b0ac4089/artifacts/windows-validation)；各版本的发布记录、校验和与 GitHub Release 不变。新版本的验证由 CI 完成，本地测试输出写到被忽略的 `artifacts/runs/`。版本号提升后，旧版本的测试结果只能作为历史基线；新版本只记录实际完成的验证。更新说明应区分开发中、已构建和已验证状态。

历史文档、日志、截图和二进制中出现的 `0.4.0` 保留原样，注明其对应工作轮次。此前 Windows 修复工作曾沿用该旧标签；现将其冻结源码按 `0.5.0` 重新构建，并单独记录重建验证。

本策略不自动执行 Git 提交、推送或远程发布。

## 0.6.1 补丁与许可记录

`0.6.1` 是 `0.6.0` 后的补丁更新，修复 Windows 默认应用入口、安装与首次启动语言选择，并完善关于窗口；不改变主要功能更新递增 MINOR、小更新递增 PATCH 的规则。具体完成状态见 [0.6.1 发布记录](RELEASE_0_6_1.md)。

自 `0.6.1` 起，当前应用源码、包清单、随包 LICENSE 和关于窗口采用 `AGPL-3.0-only`。依赖保留各自许可证；此前发行包、源码快照和验证证据保留当时的许可标识，不改写为新版本或新许可。

## 0.6.2 署名补丁

0.6.2 更新关于窗口的贡献者姓名与主页链接，继续采用小更新递增 PATCH 的规则。具体范围见 [0.6.2 发布记录](RELEASE_0_6_2.md)。

## 0.6.3 代码块与品牌显示补丁

0.6.3 修复代码块的原位编辑、语言选择及粘贴行为，更新关于标语与侧栏 Logo 尺寸，按小更新递增 PATCH。具体范围见 [0.6.3 发布记录](RELEASE_0_6_3.md)。

## 0.6.4 最终排查与发布

0.6.4 修复代码块边界操作，提供简洁的英中双语 README 和对应截图。Windows 发布只提供 NSIS 安装程序，不再构建或发布便携 ZIP。此轮用户明确要求发布最新版，按标签工作流发布 GitHub Release。

## 0.9.0 AI 写作助手改进与仓库整理
