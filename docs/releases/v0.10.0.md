# Inkstone 0.10.0

This release keeps Inkstone up to date on its own, adds a system tray, makes closing and saving safer, and publishes Linux packages.

## Download

- **Windows**: `Inkstone-0.10.0-windows-x64.exe`. The installer is not code-signed yet, so Windows SmartScreen may warn the first time; choose **More info → Run anyway**.
- **Linux (x64)**: `Inkstone-0.10.0.AppImage` (make it executable and run it), `inkstone-editor_0.10.0_amd64.deb` for Debian and Ubuntu, or `inkstone-editor-0.10.0.tar.gz`.
- `SHA256SUMS.txt` lists the checksum of every file.

If you use 0.9.2 or earlier, install 0.10.0 once by hand. Later versions arrive through the update notice.

## Automatic updates

- Inkstone checks GitHub for a new version shortly after starting and once a day. It only reads version information. You can turn this off, or check now, in **Preferences → Customize → Updates**, from **Tools → Check for updates…**, or in **About**.
- When a version is available, a bar offers **Download and install** and **What's new**. The download is verified before it is used. **Restart now** asks about unsaved changes first; otherwise the update installs when you exit.
- The Windows installation and the AppImage update themselves. The deb and tar.gz packages show a link to the release page.

## Closing and the system tray

- The first time you close the last window, Inkstone asks whether to **Minimize to Tray** or **Exit**, with **Remember my choice**. Change it later in **Preferences → Files → Closing the window**.
- In the tray, Inkstone keeps running without a taskbar button, and auto save continues. Click the icon to bring the window back. Its menu opens Inkstone or a recent document, or exits.
- Exiting from the tray, File → Quit, Ctrl+Q, Restart now and Windows shutdown all check for unsaved changes first. Minimizing to the tray does not ask.
- With several windows open, the close button closes only that window.
- Only one Inkstone runs at a time. Opening Inkstone or a Markdown file again goes to the running copy, which shows the window that already has the file open, or opens it in a new window.

## Saving and exiting

- With auto save on, closing a document that already has a file saves it without asking.
- Exiting with several unsaved documents asks once: **Save All**, **Review Each…**, **Don't Save** or **Cancel**.
- Windows shutdown, restart or sign-out waits while you have unsaved changes and asks as usual. If you choose to shut down anyway, the recovery drafts written as you type are offered the next time you start Inkstone.
- If saving fails, Inkstone says why and keeps your text:
  - The file was moved or deleted: **Save to Original Location**, or **Save As…**. Inkstone never recreates it without asking.
  - The file is read-only, in use by another program, or not writable, or the disk is full: **Save As…** or **Try Again**. Read-only files are never overwritten.
  - Auto save shows a banner and pauses instead of opening a dialog.
- Saving retries briefly when antivirus or sync software such as OneDrive holds the file for a moment.
- Canceling or a failed save never closes the document.

## Reporting problems

**Tools → Copy diagnostic information** copies a short report to paste into a GitHub issue: versions, system, settings summary and recent errors. It contains no document text, file paths or API keys.

## Validation

On Windows: 241/241 unit tests and 174/174 Electron end-to-end cases (31 and 16 new for this release), plus the installer checks and the native packaged-app smoke and interaction tests passed. The Linux packages are built and checked by the release workflow.
