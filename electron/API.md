# Inkstone desktop bridge

Supported platforms are Windows (primary) and Linux. The main process rejects other platforms, uses Ctrl shortcuts and closes the application when its last window closes. The Windows window icon uses `build/icon.ico`; Linux uses `build/icon.png`.

The isolated, sandboxed renderer gets only `window.inkstone.invoke(method, payload)`, `on(event, callback)` (returns unsubscribe), and `filePath(File)` for an actual dropped OS file. No general filesystem, shell, or IPC access is exposed. Calls throw human-readable errors; `CONFLICT:` means keep the editor buffer and offer disk reload or Save As. Cancellation returns `null` (image picker returns `[]`).

## Application and Windows integration

- `getAboutInfo({})` returns the actual application version, contributors `["Wei Zhuo"]`, contributor homepage `https://wei2hu0.github.io/`, Inkstone repository URL, AGPL-3.0-only identifier, copyright and complete bundled LICENSE text. The Tools/About command opens a renderer dialog with an offline license view.
- `getDefaultAppInfo({})` reads Windows registration and the effective Markdown default using the Shell association API. Registration and the actual default are distinct; failed or absent queries are reported explicitly.
- `openDefaultApps({})` opens a fixed Windows Default apps URI, using the matching user/machine registration on supported Windows 11 versions. Windows requires the user to confirm the default there; this operation never writes UserChoice or changes an extension default. Portable/unregistered copies use the generic Windows page and explain installation. Other platforms are unsupported for this action.
- `claimDefaultAppPrompt({})` offers the installed Windows app’s setup choice once per profile, persisting `defaultAppPrompted:true` before showing it. Competing windows cannot claim the same prompt twice.

## AI providers

AI runs in the main process and never receives filesystem editing capabilities. The renderer must request explicit user confirmation and apply revisions through the editor's normal transaction API.

- `aiGetSettings({provider?,endpoint?})` returns the active or requested safe configuration, readiness, `hasKey`, `secureStorageAvailable`, provider catalogue and per-provider profiles; never a saved key. Options include provider, endpoint, model, temperature, maxTokens, timeoutMs and an optional Anthropic workspace ID (`workspace`).
- `aiSaveSettings({...settings,apiKey?,clearKey?})` validates configuration and stores credentials using OS encryption in the user-data directory, separate from ordinary preferences. An empty key preserves an existing credential; clearKey removes it. Linux basic_text fallback is refused.
- `aiListModels({...draft})` returns `[{id,label?}]`; `aiTestConnection({...draft})` makes a small synthetic streaming request and returns `{ok,message}`. Both accept optional draft settings and `apiKey`/`clearKey` without saving them. Omit the draft to use the active saved profile. Model discovery handles Gemini/Anthropic pagination and provider-specific response formats.
- `aiStart({id,task,text,documentType,locale,question?,history?})` starts one request for the calling window and returns `{id}`. Tasks are analysis/chat; document types are general/academic/technical. Text is limited to 200,000 characters. `ai-response` events contain `{id,type,text?,message?}`; delta.text is incremental and done.text is complete. Analysis completion is validated JSON with summary, overallScore, dimensions and exact-source suggestions.
- `aiCancel({id?})` aborts only the caller's current operation. Windows closing or renderer crashes also abort requests. Endpoints are editable HTTP/HTTPS URLs with no embedded credentials, query or fragment. Credentials are scoped to provider and normalized endpoint, with safe migration from older profiles. Redirects are refused, streamed output is bounded and incomplete streams fail visibly.

`aiPanelOpen` and `aiPanelHeight` are ordinary validated editor preferences. AI conversation and document text are not written to model configuration files.

## Documents and state

- `bootstrap({})` → `{settings,session,recovery,recoverableAtStartup,version,platform,diagnostics,spellcheck,warnings,languageConfigured}`. `recovery` contains all stored drafts for the explicit recovery manager. `recoverableAtStartup` excludes draft IDs owned by any live window, preventing a new window from treating ongoing work as crashed work. A retained draft becomes eligible after its owner window closes. diagnostics contains current activeFileWatchers/activeDirectoryWatchers counts for verification. Session is the renderer's last `saveSession` object, optionally with a CLI path. Fresh profiles use the first preferred system UI language (Chinese maps to Simplified Chinese; other languages map to English). A valid saved locale takes precedence over `process.resourcesPath/installer-locale.json` (`{"locale":"en"}` or `{"locale":"zh-CN"}`). A valid saved locale, a valid installer language seed, or `firstRunComplete:true` suppresses the first-run language prompt. Installation therefore does not ask for the same language again in the app. `updateSettings({locale,firstRunComplete:true})` persists an explicit first-run choice.
- `openFile({path?,encoding?})` → `{path,text,revision,bom,lineEnding,encoding}`. Missing path opens the native picker. Text excludes BOM but retains line endings. Encoding defaults to strict UTF-8 on first open; explicit choices are utf8, utf16le, utf16be, gb18030, windows1252, shiftjis. No automatic guessing occurs. After an encoding failure from the native picker, retrying with only encoding reuses the selected path. `revision` is SHA-256 of exact bytes.
- `saveFile({path?,text,revision?,saveAs?,preserveLinks?,encoding?})` → document plus `unchanged?`. A native picker confirms overwrite when Save As is used. Otherwise revision is mandatory for existing files. Existing BOM and unaffected EOL are retained. Untouched saves do not update mtime. Save inherits the opened encoding; an explicit encoding converts only if roundtrip is lossless. Save As inherits BOM/encoding and, with preserveLinks:true, rebases parsed relative Markdown/HTML destinations without serializing the document. Code, front matter, URL/anchor destinations are preserved. A custom typora-root-url causes a returned warning instead of a guessed rewrite. Returned document text may change after rebase; the renderer must keep concurrent edits safe.
- `setDirty({dirty,title?})` → true. Set after every edit/save, including after restoring history.
- `saveSession({path,folder,selection,mode,...})` persists the complete object.
- `saveRecovery({id,path,text,revision,selection?,...})` stores a recovery snapshot atomically; `saveRecovery({id,discard:true})` or `deleteRecovery({id})` explicitly deletes it.
- `discardRecovery({id?,path?})` → `{discarded:[ids]}`. Deletes the given draft and earlier drafts for the authorized document, excluding IDs owned by other live windows. Discarded IDs are tombstoned for this process so queued or late recovery writes cannot recreate them. On a canceled close, continued editing must use a fresh recovery ID. The renderer must pause and drain pending draft writes before discarding.
- `listHistory({path})` → `[{id,path,time,size,encoding}]`, newest first; the last 100 previous versions are retained per document.
- `restoreHistory({path,id})` → historical document text with **current disk revision**, without writing the disk. Set the editor dirty and let the user save.

## Files and resources

- `chooseFolder({})` → absolute path.
- `pickPath({directory?,title?,filters?})` → path and grants access.
- `listFiles({path,recursive?,filter?,sort?})` → `[{path,name,isDirectory,size,mtime,depth}]`. Sort: name(default), modified, size. showAllFiles includes non-Markdown files. includeGlobs/excludeGlobs accept arrays or comma/newline-separated patterns; support *, ** and ?, and apply to both file trees and global search. Request fields override preferences. Hidden files (unless showHidden), symlinks, node_modules, dist, release are skipped; max 10,000 entries and 30 levels.
- `searchFiles({path,query,regex?,caseSensitive?})` → `[{path,line,text}]`. Markdown/text files, maximum 1,000 matches / 5,000 files / 5 MB per file; worker is terminated after 10 seconds to contain pathological regex. Returned snippets are at most 500 characters. The UI should state the cap.
- `fileOperation({operation,path,target?,text?})` → `{path,operation,warnings?}`. Cross-folder moves return a warning to review relative references; Save As supports destination rebasing. Operations: createFile, createFolder, rename, move, copy, trash. Create/move/copy refuse existing destinations. Trash uses OS recycle bin.
- `insertImages({documentPath,paths?,images?:[{name,dataUrl}]})` → `[{path,relativePath}]`. Missing inputs open picker. Save document first. Assets copied to imageFolder (`assets` by default, `${filename}` supported; per-document payload.imageFolder overrides the setting). Relative/absolute resource folders must stay inside previously user-authorized roots, including symlink resolution; YAML does not grant new access, identical contents deduplicated; different contents get unique names.
- `downloadImage({documentPath,url})` downloads an explicitly requested HTTP(S) image to the resource folder, validating MIME and enforcing 25 MB / 30 seconds; returns the same array as insertImages. No credentials or cookies are attached.
- `writeClipboard({text,html?,markdown?})` writes plain text, optional HTML and optional source Markdown atomically using Electron 45 ClipboardItem (10 MiB of UTF-8 per field). Markdown must equal the plain-text representation and is stored only under the fixed `text/x-inkstone-markdown` MIME type; callers cannot choose arbitrary native formats. Pending native clipboard writes finish before reads. Older Electron APIs retain plain-text/HTML compatibility.
- `clipboardImage({documentPath})` inserts native clipboard image, same return shape.
- `readAsset({path})` → data URL, up to 100 MB. Known image/media/font/CSS types only.
- Resource URL: `inkstone-asset://local/?path=${encodeURIComponent(absolutePath)}`. Only media inside user-granted roots are accessible; symlink escapes rejected. `resolveLink({documentPath,href})` resolves a relative link within an authorized root and returns `{path}`.
- `showInFolder({path})` opens the OS file manager. `openExport({path})` opens an authorized exported document/image through the OS association, rejects executable extensions, and surfaces missing-association errors.
- `openExternal({url})` accepts only HTTP(S) or mailto.

Image insertion and download accept `imageRoot` as well as `imageFolder`. Returned `markdownPath` is always URI-encoded and resolved relative to the configured image root (or document folder); remote image roots use an absolute file URL for local inserts. Legacy `relativePath` stays unencoded relative to the document when no root is configured, and equals `markdownPath` when a root is configured. Callers should prefer `markdownPath` when writing Markdown/HTML destinations. File names preserve ordinary spaces, parentheses and Unicode; publication cannot overwrite a racing destination.

## Image resource transactions

- `listImageReferences({documentPath,text,imageRoot?})` returns `{references,warnings}`. Each unique local path / remote URL has `{id,source,path?,url?,remote,occurrences}`. Occurrences include full image markup `from/to`, `destinationFrom/destinationTo` (aliases `destFrom/destTo`), `source`, `kind` (`markdown`, `reference`, `html`) and URL suffix. Positions always address the exact supplied text, including its line endings. Markdown-it block maps exclude code; source destinations are edited as spans, without Markdown serialization. Full/collapsed/shortcut references share their original definition span. Invalid definitions, embedded/data images and inaccessible resources are not guessed; embedded/inaccessible resources produce warnings. Raw HTML `<img src>` is supported; `<picture srcset>` is outside this scanner's current scope.
- `prepareImageOperation({documentPath,text,revision,encoding?,imageRoot?,imageFolder?,operation,items?,targetFolder?})` returns `{id,text,patches,resources,warnings}`. Operations: `copy`, `move`, `rename`, `download`, `unlink`, `delete`. Items are `{id,target?}`; omitted items select all compatible images, up to 100. `rename` needs one explicit target; `targetFolder` applies to batches. All paths require existing user-granted file/folder capabilities. Targets never overwrite existing files; automatically generated names get a numbered suffix. Every image is limited to 25 MB; batch total is 100 MB. Downloads require HTTP(S), verify response image MIME, and stop on timeout/failure. Preparation only writes temporary staging data, and can include the caller's unsaved document edits.
- `commitImageOperation({id})` returns the prepared fields plus `document`, which is the newly saved revision/encoding/text. Only the originating window may commit. The caller must check its original text/revision snapshot still matches and prevent editing during commit. Source images and document revisions are checked again. New resources are published atomically without overwriting existing paths; then the document is atomically saved with history. `move`, `rename` and `delete` send originals to the system trash only after the document save succeeds. Failed publication/save removes only newly created, still-unchanged files and leaves original resources/document untouched. Trash failures retain originals and return a visible warning. Other documents' references are not rewritten; the UI must communicate this before destructive resource operations. Text Undo does not restore resource files from trash.
- `unlink` removes only image markup and keeps actual files. `delete` removes image markup and trashes actual files. Shared reference definitions are kept, preserving ordinary links and surrounding source. `cancelImageOperation({id})` removes prepared staging without document/resource mutation; closing its window cancels pending prepared operations. Plans expire after 15 minutes. Interrupted operations may leave additional resource copies/staging files, but original images are not removed before a successfully saved document points to replacement resources.

## Preference migration

Image service execution, automatic image transfer, synchronization services and selected-text web search are absent from this application. Retired service keys and shortcut bindings are stripped when loading and updating settings. Successful startup migration atomically persists the cleaned preferences and reports a `bootstrap.warnings` notice. Non-service preferences, snippet/CSS contents, document bytes and local images are retained. Invalid unrelated setting types still follow the existing backup-and-default recovery path; an accompanying migration removes retired fields from that backup too. If invalid preferences cannot be backed up, automatic recent-file persistence is paused; an explicit preference change retries the backup and refuses to write while that backup still fails. The retired image-service method is rejected by both preload and main IPC. Tool detection only probes local Pandoc. Normal HTTP(S)/mailto links, remote media display, direct image URL insertion and explicitly requested HTTP(S) image downloads remain available.

## Preferences and windows

- `updateSettings(partialSettings)` also accepts strictMarkdown/cjkEmphasis/codeWrap/outlineNumbering/exportSoftBreaks, defaultCodeLanguage, themeLibrary/activeThemeName, fileSort created/name/modified/size, sortDescending and foldersFirst. Theme libraries are limited to 30 names, each containing at most 1 MB of CSS. It validates and persists, broadcasts `settings-changed`. Custom shortcuts use CodeMirror-style combinations (for example `Mod-Alt-s`); native menu accelerators are replaced with the same binding, and invalid bindings are rejected without changing existing preferences. Startup applies the same schema validation. Invalid settings types are preserved byte-for-byte as `settings.invalid-*.json` before resetting to defaults; `bootstrap.warnings` reports the reason and backup path. If backup fails, the original file remains untouched and defaults are used in memory.
- `newWindow({path?})` → `{id}`. Initial files from CLI arguments and this method are delivered once through `bootstrap.session.path`; they do not also emit an `open-path` event, which could replace edits with a late duplicate read.
- `windowAction({action,...})`: ready, requestClose, quit, closeResponse, closeCommit, fullscreen, minimize, maximize, zoom (`factor:0.5..3`), zoomIn, zoomOut, zoomReset (these return the resulting numeric zoom factor).
- `readClipboard({})` returns `{text,html,markdown,hasImage}`. Markdown is nullable and read only from the fixed Inkstone MIME representation (including the exact raw Windows alias observed for that format); it is accepted only when it matches plain text after newline normalization. All text representations are capped at 10 MiB. Default paste uses matching source Markdown before converting external HTML; explicit HTML paste always converts HTML. Keyboard copy/paste and editor context menus share this native representation. Native image data stays in the separate `clipboardImage` operation.
- `addDictionaryWord({word})` adds one word to the local session dictionary. Empty input, whitespace/control characters and words longer than 256 characters are rejected.
- The editor owns its renderer context menus, including selection-preserving formatting, insert and table submenus. Native `context-menu-details` events supply spelling suggestions without opening a duplicate OS menu; inputs outside the editor retain native menus. `contextMenu({})` remains the explicit native edit/format fallback.
- Events: `command` (string), `external-change` (`{path,revision,deleted}`), `before-close`, `before-close-commit`, `close-aborted`, `settings-changed`, `open-path` (`{path}`), `folder-change` (`{path}`). An external-change notification may be the app's own save: compare revision before showing a conflict.

Register the three close listeners before calling `windowAction({action:'ready'})`. Native close controls, File → Close, Ctrl+Q / File → Quit, and `app.quit()` all use the same coordinator, even for windows whose last reported dirty flag is false. A `before-close` request contains `{requestId,reason:'close'|'quit'}`. Freeze editing, pause timers, settle any save, ask Save / Don't Save / Cancel when needed, and reply with `windowAction({action:'closeResponse',requestId,allow,error?})`. Save As cancellation or any failure replies `allow:false`. Don't Save at this phase postpones draft deletion.

The renderer keeps its initial editor read-only throughout startup folder enumeration and initial-file loading, and sends `ready` only after that work finishes. Document navigation is serialized with composition completion and in-flight saves. Async image, formatting and resource callbacks must verify their document snapshot and lifecycle state immediately before changing the editor; CodeMirror's read-only setting does not block direct programmatic dispatches. The renderer records generation, path, text and revision at close approval, then compares that snapshot before and after commit persistence. A mismatch cancels the close and preserves the new text.

Only when every affected window approves does main send `before-close-commit` with the same requestId. Drain draft writes, delete explicitly discarded drafts, persist the session, and acknowledge `windowAction({action:'closeCommit',requestId,allow,error?})`. Main closes windows only after every commit succeeds. Any refusal in either phase emits `close-aborted` to every participating window; all windows remain open, editing resumes, and discarded dirty drafts get fresh IDs. Duplicate native close/quit requests share the same transaction. Stale or duplicate acknowledgements return false. `closeConfirmed` is a compatibility alias for the current prepare acknowledgement and cannot bypass the commit stage.

An editor that has not registered its listeners within 30 seconds of a close request gets a native Wait / Close without saving / Cancel recovery dialog. Electron's actual unresponsive signal uses the same fallback. A normal responsive Save / Don't Save / Cancel dialog has no decision timeout. Only explicit emergency approval permits destroying an unresponsive window, after the other affected windows finish both phases; existing disk recovery drafts are retained in this emergency path. New windows cannot be created during a pending close transaction.

Malformed JSON state is backed up before defaults replace it. If that backup fails, further writes to that state file are blocked and the original bytes remain intact. Preference updates retry the backup explicitly; session writes retry preserving the blocked session before continuing. Once permissions or disk errors are fixed, retry can succeed without restarting or deleting the original file.

## Offline spelling

- `spellcheckStatus({})` returns `{requested,enabled,available,initializing,languages,initializedLanguages,bundledLanguages,cachedLanguages,source,dictionaryURL,externalDownloads,error}`. `available` follows Electron's real dictionary-initialized event; `enabled` also requires the user's preference and native session enablement. Failures are reported explicitly instead of treating an inactive checker as working.
- The official Chromium `en-US-10-2.bdic` is bundled, integrity-checked, and installed into the local profile before any editor window is created. Its pinned revision, SHA-256 and source URL are in `electron/dictionaries/provenance.json`; the unmodified upstream English dictionary notices are in `README_en_US.txt`. Existing local dictionary files and custom user words are preserved. Only supported languages already present locally are activated, defaulting to bundled en-US.
- Every new Electron session is initially disabled and assigned `inkstone-dictionary://local/` synchronously. The dictionary protocol serves only checked local `.bdic` files (case-insensitive names); unavailable dictionaries return 404. There is no external-server fallback or user-facing remote dictionary service. Ordinary document URLs remain available independently.
- Chromium netlog from a fresh Linux profile and a real native context-menu misspelling/suggestion test are recorded in `artifacts/backend-validation/offline-spelling-validation.json`. Windows native validation remains pending.
- Upstream behavior: [Electron spelling documentation](https://www.electronjs.org/docs/latest/tutorial/spellchecker/) and [dictionary source configuration](https://www.electronjs.org/docs/latest/api/session#sessetspellcheckerdictionarydownloadurlurl).

## Import, export and printing

- `exportFile({format,html,css,title?,documentPath?,text?,path?,...})` → `{path?,format,warnings}`. `format`: pdf, png, jpg/jpeg, html (styled), html-plain, print, or a Pandoc export format. Missing path opens save dialog. `print` opens print dialog. Local image/media sources are embedded, as are CSS assets found inside dist and authorized inkstone-asset font/image URLs from imported CSS themes. Caller passes rendered HTML (including hydrated math/diagrams) and CSS. Main independently sanitizes HTML with vendored DOMPurify inside a sandboxed window without preload, retaining SVG/MathML while removing executable content. User scripts are disabled in export windows and exported HTML CSP. html-plain includes no application stylesheet and replaces KaTeX's dual HTML/MathML wrappers with native MathML to avoid duplicate visible formulas; MathJax/diagram SVG remains.
- PDF options: `pageSize` (A4 default), `landscape`, `bookmarks` (true default), `margins:{top,bottom,left,right}` in inches (a numeric margins value is interpreted as millimetres), `header`/`footer` HTML using Chromium's `pageNumber`, `totalPages`, `title`, `date` classes, `scale` (0.5–2). CSS page breaks are honored. PDF outlines request Chromium document outline generation; Linux E2E verifies an `/Outlines` object. Direct system printing passes page size, orientation, custom margins and plain-text headers/footers; HTML header/footer templates apply to PDF export only. Physical-printer validation remains pending.
- PNG/JPEG options: `width` (600–2400, default 1200). JPEG quality accepts 0–100 (default 90). Max output height 32,760 px; longer documents produce a clear error.
- Exports force image loading=eager, including below-viewport images, then wait up to 15 seconds for fonts and images. Missing images return warnings. Exports have no preload/Node and CSP forbids script execution.
- `detectTools({})` → `{pandoc:{available,path,version?,error?}}`; configured executable `--version` probe; Pandoc additionally reports actual `--list-input-formats` and `--list-output-formats` so behavior is tied to the installed version.
- `runPandoc({direction:'import',path?,format?})` → `{path:null,text,revision:null,importedFrom,warnings}`. Pickable inputs include docx, odt, epub, tex/latex/ltx, rst/rest, html/htm, wiki(mediawiki), dokuwiki, org, textile, opml, rtf, pptx, asciidoc/adoc, fb2, docbook, json, t2t. Actual support depends on the installed Pandoc version (3.13 adds readers absent from earlier versions). PDF import is not provided. Embedded images are extracted to a temporary directory and converted to data URIs before cleanup, so imported unsaved documents retain them offline. `direction:'format'` accepts text and returns normalized Markdown in `{text,warnings}`.
- `runPandoc({direction:'export',format,text,title?,documentPath?,path?,template?,referenceDoc?,toc?,numberSections?,args?})` → `{path,format,warnings}`. Output formats include docx, odt, rtf, epub, tex/latex/ltx, rst/rest, wiki/mediawiki, dokuwiki, org, textile, opml, pptx, revealjs, beamer, asciidoc, json, markdown/gfm/commonmark/markdown_strict/markdown_mmd, plain, s5/slidy/slideous/dzslides, docbook, fb2, texinfo, man, t2t. `pandoc-pdf` invokes Pandoc's LaTeX PDF workflow separately from native PDF and requires a TeX engine; `--pdf-engine=…` is an accepted extra option. Template/referenceDoc must be selected through file picker. Extra args are separate strings limited to formatting options; no shell, filters, input, or output overrides. Beamer PDF workflow still requires the relevant TeX engine. diagramAssets accepts [{language,source,dataUrl}] PNG renders; the export copy replaces matching Mermaid/flowchart/sequence fences with temporary PNG references before Pandoc. Each image must have a PNG signature and stay under 10 MB (100 images / 100 MB total). No caller-supplied filenames are accepted. Original Markdown remains unchanged; unmatched diagram renders return warnings. Converted output returns embeddedDiagrams and a warnings array. Complex nested fences that cannot be matched safely remain source with a warning.

`listFiles` returns `birthtime` in addition to mtime/size and accepts `sort:created|modified|size|name`, `descending`, and `foldersFirst`. `searchFiles` accepts Unicode-aware `wholeWord` and an optional request `id`; `cancelSearch({id})` terminates that window’s worker and resolves the canceled request with an empty result. Requests still have a 10-second timeout.

## Reliability boundaries

Document and export destinations are checked again before atomic replacement; exports retain the destination revision across slow rendering/conversion. Files are staged beside the destination, fsynced, revision-checked again, atomically renamed, and the directory is fsynced where supported. This protects normal crash/partial-write cases. Filesystems do not provide a portable compare-and-swap rename: an external writer in the tiny interval between final hash check and rename remains an unavoidable race. Filesystem and network-share behavior varies by platform. The first open uses strict UTF-8; users may explicitly select supported legacy encodings. Invalid byte sequences and text unrepresentable in the chosen encoding are rejected without changing disk. Every history record stores its encoding. Settings and recovery writes are queued per path so concurrent operations cannot resurrect discarded drafts or reorder preference writes. External file monitoring uses 600 ms stat polling and hashes only after metadata changes, independent of inotify quotas. Only documents active in an open window keep file watchers; open, Save As, session changes and close prune unused watchers. Active file-tree roots and at most 127 listed descendant directories use 2.5-second stat polling with debounced folder-change events. Larger trees require explicit refresh for directories beyond that cap; changing/closing folders releases their watchers. Session restore currently stores the last document/window state, not a full multi-window arrangement. The renderer must debounce recovery and auto-save and preserve changes made while an async save is pending.

## Validation on the delivery host

`tests/storage.test.cjs` covers strict/explicit encoding, unrepresentable-character refusal, exact-byte/mutation/history behavior, serialized settings/recovery writes and Save As destination-span rewrites. `tests/backend-e2e.spec.js` exercises actual Electron IPC, restricted asset paths, real image/HTML/PDF/PNG/JPEG files, imported archive images, 21 Pandoc outputs, 16 application import routes, clipboard MIME types, explicit URL downloads, settings migration, file polling and encoding retries. `artifacts/backend-validation/` contains inspected output files and `formats/manifest.json`. Windows native integrations and physical printers still require their real environments. Linux integration tests do not establish Windows validation.
